# Maintain

## Inputs

The current release, source registry, new behaviour reports or model configuration changes.

## Steps

1. Run Maintain after changing a model setting or receiving a relevant report.
2. Test released instructions unchanged before proposing a workaround.
3. Read failed outputs and separate behaviour failures from blocked execution.
4. Review source-update Issues and request analysis only for useful changes.
5. Reproduce material regressions and create a focused Develop change.
6. Test whether an old workaround can be removed. Keep user requirements unless the user changes them.
7. Update existing Issues rather than creating duplicate work.

## Completion evidence

Dated compatibility results, raw run evidence and any required follow-up Issue.
Historical release evidence remains unchanged.
Manual targets require new recorded sessions; scheduled jobs do not impersonate them.

## Hand-off

Use Ingest for source changes and Develop for instruction changes.
